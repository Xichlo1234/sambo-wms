PHẦN 1 - DỌN Ổ C (cần trống ít nhất 5 GB)
=====================================================================
Không tự xóa tay bất cứ thứ gì trong C:\Windows, C:\Program Files,
C:\ProgramData.

1.1 Tắt ngủ đông (giải phóng 3-8 GB)  [PowerShell Admin]
    powercfg /h off

1.2 Dọn file rác hệ thống (1-10 GB)
    - Start -> gõ Disk Cleanup -> chọn ổ C:
    - Bấm "Clean up system files" -> chọn lại ổ C:
    - Tích TẤT CẢ các mục (đặc biệt Windows Update Cleanup, Delivery
      Optimization Files, Temporary files, Recycle Bin, Previous
      Windows installation) -> OK -> Delete Files.
    - Xóa file tạm của người dùng  [PowerShell Admin]:
      Remove-Item "$env:TEMP\*" -Recurse -Force -ErrorAction SilentlyContinue

1.3 Chuyển bộ nhớ ảo (pagefile) sang ổ D (2-8 GB)
    - Start -> gõ sysdm.cpl -> Enter -> tab Advanced -> Performance:
      Settings -> tab Advanced -> Virtual memory: Change
    - Bỏ tích "Automatically manage paging file size..."
    - Chọn ổ C: -> chọn "No paging file" -> Set (cảnh báo bấm Yes)
    - Chọn ổ D: -> chọn "System managed size" -> Set -> OK
    - Khởi động lại máy.

1.4 Chuyển thư mục cá nhân sang ổ D
    Với từng thư mục Downloads, Documents, Desktop, Pictures, Videos:
    File Explorer -> chuột phải thư mục -> Properties -> tab Location
    -> Move -> chọn thư mục trên ổ D (vd D:\Users\Downloads) -> Apply
    -> Yes (chuyển file cũ sang).

1.5 Chuyển dữ liệu Zalo sang ổ D (thường rất nặng)
    Zalo PC -> Cài đặt -> Dữ liệu -> Thay đổi thư mục lưu trữ
    -> chọn D:\ZaloData. Có thể xóa ảnh/video cũ không cần.

1.6 Nén Windows (khoảng 2 GB)  [PowerShell Admin]
    compact /compactos:always

1.7 Gỡ phần mềm không dùng
    Settings -> Apps -> Installed apps -> sắp xếp theo Size -> gỡ.
    Xóa cache trình duyệt: trong Chrome/Edge nhấn Ctrl+Shift+Delete
    -> All time -> Cached images and files -> Clear.

1.8 Kiểm tra: mở This PC, ổ C phải trống >= 5 GB mới làm tiếp.
    (Còn thiếu: cài WizTree vào ổ D, quét ổ C để tìm thư mục nặng.)

PHẦN 2 - CÀI UBUNTU (WSL2) VÀO Ổ D
=====================================================================
Yêu cầu: Windows 10 bản 21H2 trở lên hoặc Windows 11
(kiểm tra: Start -> gõ winver -> Enter).

2.1 [PowerShell Admin] - cập nhật WSL:
    wsl --update

2.2 Tạo thư mục trên ổ D:
    mkdir D:\WSL\Ubuntu

2.3 Cài Ubuntu vào ổ D:
    wsl --install -d Ubuntu --location D:\WSL\Ubuntu

    - Nếu yêu cầu khởi động lại -> khởi động lại máy.
    - Cửa sổ Ubuntu mở ra: đặt username (chữ thường, không dấu,
      vd: sambo) và mật khẩu (ghi vào danh sách ở đầu tài liệu).
    - Nếu báo lỗi về virtualization: vào BIOS bật Intel VT-x
      hoặc AMD-V (SVM), rồi làm lại 2.3.

    >>> Nếu 2.3 báo lỗi "--location" không hợp lệ, làm cách thay thế:
        a) wsl --install -d Ubuntu      (đặt username sambo + mật khẩu,
                                          xong gõ exit)
        b) wsl --shutdown
        c) wsl --export Ubuntu D:\ubuntu-backup.tar
        d) wsl --unregister Ubuntu
        e) wsl --import Ubuntu D:\WSL\Ubuntu D:\ubuntu-backup.tar
        f) wsl -d Ubuntu -u root -- bash -c "printf '[user]\ndefault=sambo\n[boot]\nsystemd=true\n' > /etc/wsl.conf"
        g) wsl --shutdown
        h) Xóa file D:\ubuntu-backup.tar
        (thay "sambo" bằng username bạn đã đặt nếu khác)

2.4 Kiểm tra  [PowerShell Admin]:
    wsl -l -v
    -> phải thấy Ubuntu, VERSION 2. Thư mục D:\WSL\Ubuntu có file
       ext4.vhdx (toàn bộ Ubuntu nằm trong file này).

2.5 Kiểm tra systemd  [Ubuntu]:
    systemctl is-system-running
    -> "running" hoặc "degraded" là ĐƯỢC.
    -> Nếu báo "System has not been booted with systemd":
       [Ubuntu]   printf '[boot]\nsystemd=true\n' | sudo tee -a /etc/wsl.conf
       [PowerShell Admin]   wsl --shutdown
       Mở lại Ubuntu, kiểm tra lại.

2.6 Cập nhật Ubuntu  [Ubuntu]:
    sudo apt update && sudo apt upgrade -y
    sudo apt install -y git curl

PHẦN 6 - CHUYỂN CƠ SỞ DỮ LIỆU SANG SUPABASE
=====================================================================
6.1 [Ubuntu] - ghi chuỗi Supabase vào cấu hình. Thay <CHUOI_SUPABASE>
    bằng chuỗi ở 3.3, GIỮ NGUYÊN 2 dấu nháy đơn:
    sudo sed -i "s#^DATABASE_URL=.*#DATABASE_URL='<CHUOI_SUPABASE>'#" /opt/sambo-wms/shared/.env

    Kiểm tra (phải thấy chuỗi pooler.supabase.com):
    sudo grep DATABASE_URL /opt/sambo-wms/shared/.env

6.2 Tạo bảng và dữ liệu ban đầu trên Supabase (mật khẩu admin vẫn là
    mật khẩu đã ghi ở 5.2):
    cd /opt/sambo-wms/current/server && sudo -u wms bash -c 'set -a; . /opt/sambo-wms/shared/.env; set +a; npx prisma migrate deploy && npx tsx prisma/seed.ts'

    -> phải thấy "All migrations have been successfully applied"
       và "Seed hoàn tất".

6.3 Cài công cụ sao lưu đúng phiên bản Supabase.
    Xem phiên bản trên Supabase: Project Settings -> Infrastructure
    (thường là 17; nếu là 15 thì thay số 17 bằng 15 ở 2 lệnh dưới).
    sudo apt install -y postgresql-common && sudo /usr/share/postgresql-common/pgdg/apt.postgresql.org.sh -y
    sudo apt install -y postgresql-client-17
    sudo sed -i 's#^PG_BIN_DIR=.*#PG_BIN_DIR=/usr/lib/postgresql/17/bin#' /opt/sambo-wms/shared/.env

6.4 Khởi động lại và kiểm tra:
    sudo systemctl restart sambo-wms && sleep 5 && curl http://localhost:4000/api/health

6.5 Tắt cơ sở dữ liệu nội bộ không còn dùng (tiết kiệm RAM):
    sudo systemctl disable --now postgresql

6.6 Khóa truy cập công khai trên Supabase:
    Supabase -> SQL Editor -> New query -> dán 3 dòng -> Run:
    REVOKE ALL ON ALL TABLES IN SCHEMA public FROM anon, authenticated;
    REVOKE ALL ON ALL SEQUENCES IN SCHEMA public FROM anon, authenticated;
    ALTER DEFAULT PRIVILEGES IN SCHEMA public REVOKE ALL ON TABLES FROM anon, authenticated;

    Kiểm tra: Supabase -> Table Editor thấy các bảng items,
    chemical_batches, purchase_orders...

PHẦN 8 - ĐƯA RA INTERNET BẰNG CLOUDFLARE TUNNEL
=====================================================================
Yêu cầu: có tên miền đã thêm vào Cloudflare (gói Free).
(Chưa có: dash.cloudflare.com -> Add a site -> chọn Free -> đổi
nameserver tại nơi mua tên miền -> chờ Cloudflare báo Active.)

8.1 dash.cloudflare.com -> Zero Trust -> Networks -> Tunnels
    -> Create a tunnel -> chọn Cloudflared -> tên: sambo-wms -> Save.
8.2 Chọn môi trường: Debian, 64-bit. Cloudflare hiện các lệnh cài.
    Chép và chạy TỪNG lệnh trong cửa sổ [Ubuntu]. Lệnh cuối có dạng:
    sudo cloudflared service install eyJhIjoi.....
    -> Trên trang Cloudflare, Connector chuyển "Connected" là được.
8.3 Bấm Next -> Public Hostname:
    - Subdomain: wms
    - Domain: <ten-mien-cong-ty>
    - Service Type: HTTP ; URL: localhost:4000
    -> Save tunnel.
8.4 [Ubuntu] - bật cookie bảo mật HTTPS:
    sudo sed -i 's/^COOKIE_SECURE=.*/COOKIE_SECURE=true/' /opt/sambo-wms/shared/.env && sudo systemctl restart sambo-wms
8.5 Mở https://wms.<ten-mien-cong-ty> (thử cả trên điện thoại dùng 4G)
    -> đăng nhập được là XONG.
    LƯU Ý: từ đây luôn dùng địa chỉ https://wms... (vào bằng
    http://localhost:4000 sẽ không giữ được đăng nhập).

8.6 Chỉ cho nhân viên công ty vào (khuyến nghị, miễn phí <= 50 người):
    Zero Trust -> Access -> Applications -> Add an application
    -> Self-hosted -> Application domain: wms.<ten-mien-cong-ty>
    -> Add policy: Action = Allow ; Include = Emails ending in
       @<ten-mien-email-cong-ty>  (hoặc "Emails" và nhập từng email)
    -> Save. Người dùng sẽ nhận mã qua email trước khi tới trang
       đăng nhập SAMBO WMS.

PHẦN 9 - SAO LƯU NGOÀI SITE LÊN CLOUDFLARE R2 (miễn phí 10 GB)
=====================================================================
9.1 Cloudflare -> R2 Object Storage (lần đầu cần bật R2, gói Free)
    -> Create bucket: sambo-wms-backup
9.2 R2 -> Manage API tokens -> Create API token
    -> Permissions: Object Read & Write -> Apply to: sambo-wms-backup
    -> Create. Ghi lại: Access Key ID, Secret Access Key, Endpoint
    (dạng https://<id>.r2.cloudflarestorage.com).
9.3 [Ubuntu]:
    sudo apt install -y rclone
    sudo rclone config
    Trả lời lần lượt:
      n                      (New remote)
      name> r2
      Storage> s3            (gõ s3 hoặc số tương ứng "Amazon S3...")
      provider> Cloudflare
      env_auth> (Enter)
      access_key_id> <Access Key ID>
      secret_access_key> <Secret Access Key>
      region> (Enter)
      endpoint> <Endpoint>
      các câu còn lại: Enter ; cuối cùng: y (Yes this is OK) ; q (Quit)
9.4 Thử sao lưu và đẩy lên R2 ngay:
    sudo R2_REMOTE=r2:sambo-wms-backup bash /opt/sambo-wms/current/deploy/backup.sh
    -> thấy "Kiểm tra toàn vẹn: OK" và "Đã đồng bộ lên r2:..."
9.5 Đặt lịch tự động 2 giờ sáng hằng ngày:
    echo '0 2 * * * root R2_REMOTE=r2:sambo-wms-backup bash /opt/sambo-wms/current/deploy/backup.sh' | sudo tee /etc/cron.d/sambo-wms-r2
9.6 Trên Cloudflare: bucket sambo-wms-backup -> Settings
    -> Object lifecycle rules -> xóa file cũ hơn 90 ngày.
(Sao lưu hằng đêm cũng giữ dự án Supabase luôn hoạt động, không bị
 tạm dừng do "không hoạt động".)

     Start -> gõ Task Scheduler -> Create Task (bên phải)

       logged on"
     - Tab Triggers: New -> Begin the task: At log on -> OK
     - Tab Actions: New -> Program/script:
           C:\Windows\System32\wsl.exe
       Add arguments:
           -d Ubuntu --exec sleep infinity
       -> OK
     - Tab Conditions: BỎ tích "Start the task only if the computer is
       on AC power"
     - Tab Settings: BỎ tích "Stop the task if it runs longer than"
     -> OK
10.4 Windows Update -> Advanced options -> Active hours: đặt theo giờ
     làm việc để máy không tự khởi động lại trong giờ làm việc.
10.5 Kiểm tra: khởi động lại máy -> đăng nhập Windows -> chờ 1-2 phút
     -> mở https://wms.<ten-mien-cong-ty> trên điện thoại (4G).
LƯU Ý: máy phải BẬT và ĐÃ ĐĂNG NHẬP Windows thì hệ thống mới chạy.
Khi vận hành chính thức, nên chuyển sang mini-PC cài Ubuntu hoặc VPS:

PHẦN 13 - LỆNH VẬN HÀNH THƯỜNG DÙNG  [Ubuntu]
=====================================================================
Xem trạng thái ứng dụng ..... sudo systemctl status sambo-wms
Khởi động lại ứng dụng ...... sudo systemctl restart sambo-wms
Xem nhật ký lỗi ............. sudo journalctl -u sambo-wms -n 100
Kiểm tra sức khỏe ........... curl http://localhost:4000/api/health
Trạng thái Cloudflare Tunnel  sudo systemctl status cloudflared
Sao lưu thủ công ............ sudo bash /opt/sambo-wms/current/deploy/backup.sh
Danh sách bản sao lưu ....... ls -lh /var/lib/sambo-wms/backups
Khôi phục khi sự cố ......... sudo bash /opt/sambo-wms/current/deploy/restore.sh /var/lib/sambo-wms/backups/<ten-file>.dump
Xem cấu hình ................ sudo cat /opt/sambo-wms/shared/.env


=====================================================================
PHẦN 14 - XỬ LÝ SỰ CỐ THƯỜNG GẶP
=====================================================================
* wsl --install báo "Invalid distribution name"
  -> chạy: wsl --list --online ; dùng đúng tên trong danh sách.
* WSL báo lỗi virtualization
  -> bật Intel VT-x / AMD-V trong BIOS; Windows Features bật
     "Virtual Machine Platform".
* curl .../api/health không trả về "ok"
  -> sudo journalctl -u sambo-wms -n 50 (thường sai DATABASE_URL).
* Lỗi kết nối Supabase
  -> dùng đúng Session pooler cổng 5432; mật khẩu có ký tự đặc biệt
     phải đặt lại chỉ chữ+số; kiểm tra dự án Supabase có bị Paused
     không (bấm Restore project).
* Đăng nhập xong bị đẩy ra ngay
  -> đang vào bằng http:// trong khi đã bật COOKIE_SECURE=true
     -> dùng https://wms.<ten-mien>.
* Trang Cloudflare báo lỗi 502 / 1033
  -> ứng dụng hoặc tunnel chưa chạy: sudo systemctl status sambo-wms
     và sudo systemctl status cloudflared ; máy Windows có đang bật
     và đã đăng nhập không.
* Sao lưu báo lỗi phiên bản pg_dump
  -> làm lại 6.3 đúng phiên bản Supabase.
* Hết dung lượng ổ D
  -> xóa bản sao lưu cũ trong /var/lib/sambo-wms/backups (đã có bản
     trên R2).
